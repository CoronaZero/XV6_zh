# 代码：C 引导

> 来源：book-rev7.pdf，第 87–91 页（中文翻译）

引导加载器的 C 部分 bootmain.c (8500) 期望在磁盘上从第二个扇区开始找到内核可执行文件的副本。内核是 ELF 格式的二进制，如第 2 章所见。为了访问 ELF 头部，bootmain 加载 ELF 二进制的前 4096 字节 (8514)。它将内存副本放在地址 0x10000。下一步是快速检查这很可能是 ELF 二进制，而不是未初始化的磁盘。bootmain 从磁盘上 ELF 头部起始处偏移 off 字节的位置读取段内容，并写入从地址 paddr 开始的内存。Bootmain 调用 readseg 从磁盘加载数据 (8538)，调用 stosb 将段的其余部分清零 (8540)。stosb (0492) 使用 x86 指令 rep stosb 初始化一块内存的每个字节。

内核已被编译和链接，因此它期望在从 0x80100000 开始的虚拟地址找到自己。也就是说，函数调用指令引用看起来像 0x801xxxxx 的目的地地址；你可以在 kernel.asm 中看到例子。这个地址在 kernel.ld 中配置。0x80100000 是一个相对较高的地址，接近 32 位地址空间的末尾；第 2 章解释了选择这个地址的原因。这么高的地址可能没有任何物理内存。一旦内核开始执行，它将设置分页硬件，把从 0x80100000 开始的虚拟地址映射到从 0x00100000 开始的物理地址；内核假定在这个较低的地址存在物理内存。然而，在引导过程的这个时刻，分页尚未启用。相反，kernel.ld 指定 ELF paddr 从 0x00100000 开始，这使引导加载器将内核复制到分页硬件最终将指向的低物理地址。

引导加载器的最后一步是调用内核的入口点，即内核期望开始执行的指令。对于 xv6，入口地址是：

```c
0x10000c:
# objdump -f kernel
kernel: file format elf32-i386
architecture: i386, flags 0x00000112:
EXEC_P, HAS_SYMS, D_PAGED
start address 0x0010000c
```

按照惯例，_start 符号指定 ELF 入口点，定义在文件 entry.S (1036) 中。由于 xv6 尚未设置虚拟内存，xv6 的入口点是 entry (1040) 的物理地址。
