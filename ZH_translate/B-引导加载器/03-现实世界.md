# 现实世界

> 来源：book-rev7.pdf，第 87–91 页（中文翻译）

本附录描述的引导加载器编译后约有 470 字节的机器代码，具体取决于编译 C 代码时使用的优化。为了容纳到这么小的空间，xv6 引导加载器做了一个主要的简化假设：内核已从扇区 1 开始连续写入引导磁盘。更常见的是，内核存储在普通文件系统中，可能不连续，或通过网络加载。这些复杂性要求引导加载器能够驱动各种磁盘和网络控制器，并理解各种文件系统和网络协议。换句话说，引导加载器本身必须是一个小型操作系统。由于如此复杂的引导加载器肯定无法容纳在 512 字节中，大多数 PC 操作系统使用两步引导过程。首先，像本附录这样的简单引导加载器从已知磁盘位置加载功能完整的引导加载器，通常依赖空间限制较少的 BIOS 进行磁盘访问，而不是尝试自己驱动磁盘。然后，摆脱了 512 字节限制的完整加载器可以实现定位、加载和执行所需内核所需的复杂性。也许更现代的设计是让 BIOS 直接从磁盘读取更大的引导加载器（并以保护和 32 位模式启动它）。

本附录的写法就好像从加电到引导加载器执行之间唯一发生的事情就是 BIOS 加载引导扇区。事实上，BIOS 进行了大量的初始化，使现代计算机的复杂硬件看起来像传统标准 PC。
