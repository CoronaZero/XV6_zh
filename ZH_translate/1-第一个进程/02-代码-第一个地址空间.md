# 代码：第一个地址空间

> 来源：book-rev7.pdf，第 17–24 页（中文翻译）

![图 1-2](../../PIC/Figure-1-2.png)

（图 1-2：虚拟地址空间与物理内存的布局——虚拟地址空间中 0x80000000 到 0xFFFFFFFF 为 BIOS、内核文本与数据；物理内存中 0 到 4 Mbyte 为 BIOS、内核文本与数据。）

当 PC 上电时，它初始化自身，然后从磁盘加载一个引导加载器到内存并执行它。附录 B 解释了细节。xv6 的引导加载器从磁盘加载 xv6 内核，并从 entry (1040) 开始执行。内核启动时，x86 分页硬件尚未启用，虚拟地址直接映射到物理地址。

引导加载器把 xv6 内核加载到内存的物理地址 0x100000。它没有把内核加载到内核期望找到其指令和数据的地方 0x80100000，因为小型机器上那么高的地址可能没有物理内存。它把内核放在 0x100000 而不是 0x0，则是因为地址范围 0xa0000:0x100000 包含 I/O 设备。

为了允许内核其余部分运行，entry 建立一张页表，把从 0x80000000 开始的虚拟地址（称为 KERNBASE (0207)）映射到从 0x0 开始的物理地址（见图 1-1）。建立两段映射到同一物理内存范围的虚拟地址区域是页表的常见用途，我们还会看到更多类似例子。

entry 页表定义在 main.c (1311)。我们在第 2 章讨论页表的细节，但简言之：entry 0 项将虚拟地址 0:0x400000 映射到物理地址 0:0x400000。只要 entry 在低地址执行，就需要这个映射，但它最终会被移除。entry 960 将虚拟地址 KERNBASE:KERNBASE+0x400000 映射到物理地址 0:0x400000。这一项会在 entry 完成之后被内核使用；它把内核期望找到指令和数据的高虚拟地址映射到引导加载器放置它们的低物理地址。这个映射把内核指令和数据限制为 4 Mbytes。

回到 entry：它将 entrypgdir 的物理地址加载到控制寄存器 %cr3 中。分页硬件必须知道 entrypgdir 的物理地址，因为它还无法翻译虚拟地址，还没有页表。符号 entrypgdir 指代高内存中的某个地址，宏 V2P_WO (0220) 减去 KERNBASE 以得到物理地址。为启用分页硬件，xv6 在控制寄存器 %cr0 中设置 CR0_PG 标志。

启用分页后，处理器仍在低地址执行指令，这能工作是因为 entrypgdir 映射了低地址。如果 xv6 从 entrypgdir 中省略了 entry 0 项，那么在启用分页的那条指令之后，计算机执行下一条指令时会崩溃。

现在 entry 需要把控制转移给内核的 C 代码，并让其在内存的高地址中运行。首先它使栈指针 %esp 指向一块用作栈的内存 (1054)。所有符号都有高地址，包括 stack，因此即使在低映射移除后，该栈仍然有效。最后 entry 跳转到 main，main 也是一个高地址。间接跳转是必要的，因为汇编器否则会生成 PC 相对的直接跳转，执行低内存版本的 main。main 不能返回，因为栈上不存在返回地址。现在内核在函数 main (1217) 中以高地址运行。
