# 代码：运行第一个进程

> 来源：book-rev7.pdf，第 17–24 页（中文翻译）

现在第一个进程的状态已准备好，是时候运行它了。main 调用 userinit 之后，mpmain 调用 scheduler 开始运行进程 (1267)。scheduler (2458) 查找 p->state 为 RUNNABLE 的进程，这里只有一个：initproc。它将每 CPU 变量 proc 设置为找到的进程，并调用 switchuvm 让硬件开始使用目标进程的页表 (1768)。在内核执行期间切换页表是可行的，因为 setupkvm 使所有进程的页表对内核代码和数据有相同的映射。switchuvm 还设置了一个任务状态段 SEG_TSS，它指示硬件在进程的内核栈上执行系统调用和中断。我们将在第 3 章重新讨论任务状态段。

然后 scheduler 将 p->state 设为 RUNNING 并调用 swtch (2708) 执行到目标进程内核线程的上下文切换。swtch 保存当前寄存器，并把目标内核线程的已保存寄存器（proc->context）加载到 x86 硬件寄存器中，包括栈指针和指令指针。当前上下文不是进程，而是一个特殊的每 CPU 调度器上下文，因此 scheduler 告诉 swtch 把当前的硬件寄存器保存到每 CPU 存储（cpu->scheduler）中，而不是任何进程的内核线程上下文中。我们将在第 5 章更详细地研究 swtch。最后的 ret 指令 (2727) 从栈中弹出目标进程的 %eip，完成上下文切换。现在处理器运行在进程 p 的内核栈上。

allocproc 将 initproc 的 p->context->eip 设置为 forkret，因此 ret 开始执行 forkret。在第一次调用时（也就是这一次），forkret (2533) 运行那些不能从 main 运行的初始化函数，因为它们必须在拥有自己的内核栈的普通进程上下文中运行。随后，forkret 返回。allocproc 安排了 p->context 被弹出后，栈顶的下一项将是 trapret，所以现在 trapret 开始执行，%esp 指向 p->tf。trapret (3027) 使用 pop 指令恢复 trap frame（0602）中的寄存器，就像 swtch 对内核上下文所做的那样：popal 恢复通用寄存器，然后 popl 指令恢复 %gs、%fs、%es 和 %ds。addl 跳过 trapno 和 errcode 两个字段。最后，iret 从栈上弹出 %cs、%eip、%flags、%esp 和 %ss。trap frame 的内容已转移到 CPU 状态，因此处理器继续在 trap frame 中指定的 %eip 处执行。对于 initproc，这意味着虚拟地址 0，即 initcode.S 的第一条指令。

此时 %eip 为 0，%esp 为 4096。这些是进程地址空间中的虚拟地址。处理器的分页硬件将它们翻译为物理地址。allocuvm 建立了进程的页表，使虚拟地址 0 指向为该进程分配的物理内存，并设置了一个标志（PTE_U），告诉分页硬件允许用户代码访问该内存。userinit (2264) 设置 %cs 的低位，使进程的用户代码在 CPL=3 运行，这意味着用户代码只能使用设置了 PTE_U 的页，不能修改 %cr3 等敏感硬件寄存器。因此进程被限制为只能使用自己的内存。
