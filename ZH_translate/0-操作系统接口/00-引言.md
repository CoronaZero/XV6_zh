# 引言

> 来源：book-rev7.pdf，第 7–16 页（中文翻译）

操作系统的工作是在多个程序之间共享一台计算机，并提供比硬件本身所能支持的更有用的服务集合。操作系统管理和抽象底层硬件，例如，字处理器无须关心正在使用哪种类型的磁盘硬件。操作系统还对硬件进行多路复用，允许多个程序共享计算机并同时运行（或看起来同时运行）。最后，操作系统提供受控的程序间交互方式，使它们能够共享数据或协同工作。

操作系统通过一个接口向用户程序提供服务。设计一个好的接口是困难的。一方面，我们希望接口简单而狭小，因为这样更容易把实现做对；另一方面，我们又可能想为应用程序提供许多复杂精巧的特性。解决这种紧张关系的诀窍在于：设计依靠少数几个机制、并能组合出极大通用性的接口。

本书用一个具体的操作系统作为示例来阐明操作系统概念。这个操作系统，即 xv6，提供了由 Ken Thompson 与 Dennis Ritchie 的 Unix 操作系统引入的基本接口，并且模仿了 Unix 的内部设计。Unix 提供了一个接口狭小但机制组合良好的系统，展现出惊人的通用程度。这一接口如此成功，以至于现代操作系统——BSD、Linux、Mac OS X、Solaris，甚至在较小程度上包括 Microsoft Windows——都拥有类 Unix 的接口。理解 xv6 是理解这些系统以及其他许多系统的良好起点。

如图 0-1 所示，xv6 采用传统的内核形式：内核是一个向运行中的程序提供服务的中内核。每个运行中的程序称为进程，其内存包含指令、数据和栈。指令实现程序的计算；数据是计算所作用的变量；栈组织了程序的函数调用。

当进程需要调用某个内核服务时，它会在操作系统中调用某个内核接口函数。这种函数称为系统调用。系统调用进入内核，内核执行服务并返回。因此进程在用户空间与内核空间之间交替执行。

内核利用 CPU 的硬件保护机制，确保在用户空间执行的每个进程只能访问自己的内存。内核拥有实现这些保护所需的硬件特权；用户程序则不具备这些特权。当用户程序发起系统调用时，硬件提升特权级别，并开始执行内核中预先安排好的函数。

内核所提供的全部系统调用的集合，就是用户程序看到的接口。xv6 内核提供了传统 Unix 内核所提供服务与系统调用的子集。这些调用如下：

| 系统调用 | 描述 |
| --- | --- |
| fork() | 创建进程 |
| exit() | 终止当前进程 |
| wait() | 等待一个子进程退出 |
| kill(pid) | 终止进程 pid |
| getpid() | 返回当前进程的 pid |
| sleep(n) | 睡眠 n 秒 |
| exec(filename, *argv) | 加载一个文件并执行它 |
| sbrk(n) | 将进程内存扩大 n 字节 |
| open(filename, flags) | 打开文件；flags 表示读/写 |
| read(fd, buf, n) | 从打开的文件 fd 读 n 字节到 buf |
| write(fd, buf, n) | 向打开的文件 fd 写 n 字节 |
| close(fd) | 释放打开的文件 fd |
| dup(fd) | 复制 fd |
| pipe(p) | 创建管道，并将读写 fd 放入 p |
| chdir(dirname) | 改变当前目录 |
| mkdir(dirname) | 创建新目录 |
| mknod(name, major, minor) | 创建设备文件 |
| fstat(fd) | 返回打开文件 fd 的信息 |
| link(f1, f2) | 为文件 f1 创建另一个名字 f2 |
| unlink(filename) | 移除一个文件 |

本章其余部分概述 xv6 的服务——进程、内存、文件描述符、管道与文件系统——并用代码片段和 shell 调用这些服务的讨论加以说明。shell 对系统调用的使用，说明了这些系统调用是经过多么精心设计的。

shell 是一个普通程序，它从用户读取命令并执行这些命令，是传统类 Unix 系统的主要用户接口。shell 是用户程序而非内核的一部分，这一事实说明了系统调用接口的强大：shell 没有任何特殊之处。这也意味着 shell 易于替换；因此，现代 Unix 系统提供了多种可选的 shell，各有各的用户接口与脚本特性。xv6 的 shell 是 Unix Bourne shell 核心的简单实现。其实现在第 (7850) 行。
