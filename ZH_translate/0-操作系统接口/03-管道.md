# 管道

> 来源：book-rev7.pdf，第 7–16 页（中文翻译）

管道是一个小型内核缓冲区，以一对文件描述符的形式暴露给进程，一个用于读，一个用于写。向管道一端写数据，可以使该数据从管道另一端被读取。管道为进程提供了一种通信方式。

下面的示例代码运行程序 wc，其标准输入连接到管道的读端。

```c
int p[2];
char *argv[2];
argv[0] = "wc";
argv[1] = 0;
pipe(p);
if(fork() == 0) {
close(0);
dup(p[0]);
close(p[0]);
close(p[1]);
exec("/bin/wc", argv);
} else {
write(p[1], "hello world\n", 12);
close(p[0]);
close(p[1]);
}
```

程序调用 pipe，它创建一个新管道，并把读写文件描述符记录在数组 p 中。fork 之后，父进程和子进程都拥有指向该管道的文件描述符。子进程把读端复制到文件描述符 0，关闭 p 中的文件描述符，并 exec wc。当 wc 从其标准输入读取时，它读取的是管道。父进程向管道写端写入，然后关闭它的两个文件描述符。

如果没有数据可用，对管道的 read 会等待，直到有数据被写入，或者所有指向写端的文件描述符都被关闭；在后一种情况下，read 返回 0，就像到达了数据文件末尾一样。read 会一直阻塞到不可能再有新数据到达，这一事实是子进程在 exec wc 之前必须关闭管道写端的原因之一：如果 wc 的某个文件描述符指向管道的写端，wc 将永远看不到文件结束。

xv6 shell 以与上述代码类似的方式实现管道，例如 grep fork sh.c | wc -l (7950)。子进程创建管道来连接左端与右端，然后为左端调用 runcmd、为右端调用 runcmd，并两次调用 wait 等待左端与右端结束。管道的右端可能是一个本身包含管道的命令（如 a | b | c），它自身会 fork 两个新的子进程（一个给 b，一个给 c）。因此，shell 可能创建一个进程树。这棵树的叶子是命令，内部节点是等待左、右子树完成的进程。原则上可以让内部节点运行管道左端的命令，但正确地这样做会使实现变得复杂。

管道看起来并不比临时文件更强：管道

```c
echo hello world | wc
```

可以不用管道实现为

```c
echo hello world >/tmp/xyz; wc </tmp/xyz
```

管道与临时文件之间至少有三个关键区别。第一，管道会自动清理自己；使用文件重定向时，shell 必须注意在使用完毕后删除 /tmp/xyz。第二，管道可以传递任意长度的数据流，而文件重定向需要磁盘上有足够的空闲空间来存储所有数据。第三，管道支持同步：两个进程可以借助一对管道来回发送消息，每次读取都会阻塞其调用进程，直到另一进程用 write 发送了数据。
