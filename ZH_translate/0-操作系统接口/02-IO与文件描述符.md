# I/O 与文件描述符

> 来源：book-rev7.pdf，第 7–16 页（中文翻译）

文件描述符是一个小整数，表示一个由内核管理的对象，进程可以从中读取或向其写入。进程可以通过打开文件、目录或设备，或通过创建管道，或通过复制已有描述符来获得文件描述符。为简便起见，我们常常把文件描述符所指的对象称为“文件”；文件描述符接口抽象了文件、管道和设备之间的差异，使它们看起来都像字节流。

在内部，xv6 内核把文件描述符用作进程私有表的索引，因此每个进程都有从零开始的文件描述符私有空间。按惯例，进程从文件描述符 0（标准输入）读取，向文件描述符 1（标准输出）写输出，向文件描述符 2（标准错误）写错误消息。稍后我们将看到，外壳正是利用这一惯例实现 I/O 重定向与管道。外壳确保自己始终打开三个文件描述符 (8007)，默认是控制台的文件描述符。

read 和 write 系统调用从文件描述符命名的打开文件中读取和写入字节。调用 read(fd, buf, n) 从文件描述符 fd 读取最多 n 字节，复制到 buf 中，并返回实际读到的字节数。每个指向文件的文件描述符都关联一个偏移量。read 从当前文件偏移处读取数据，然后按读取的字节数推进偏移量：随后的 read 将返回第一次 read 返回字节之后的字节。当没有更多字节可读时，read 返回 0 表示文件结束。调用 write(fd, buf, n) 从 buf 向文件描述符 fd 写入 n 字节，并返回写入的字节数。只有当出错时才会少于 n 字节。与 read 一样，write 从当前文件偏移处写入数据，然后按写入的字节数推进偏移量：每次 write 都从上一次结束处继续。

下面的程序片段（构成了 cat 的核心）将数据从标准输入复制到标准输出。如果出错，它会向标准错误写一条消息。

```c
char buf[512];
int n;
for(;;){
n = read(0, buf, sizeof buf);
if(n == 0)
break;
if(n < 0){
fprintf(2, "read error\n");
exit();
}
if(write(1, buf, n) != n){
fprintf(2, "write error\n");
exit();
}
}
```

这个代码片段值得注意的重要一点是：cat 并不知道自己是在从文件、控制台还是管道读取。同样，cat 也不知道自己是向控制台、文件还是别的什么输出。文件描述符的使用，以及文件描述符 0 是输入、文件描述符 1 是输出的惯例，使 cat 的实现非常简单。

close 系统调用释放一个文件描述符，使其可被将来的 open、pipe 或 dup 系统调用（见下文）重新使用。新分配的文件描述符始终是当前进程编号最小的未用描述符。

文件描述符与 fork 的相互作用使 I/O 重定向易于实现。fork 把父进程的文件描述符表连同其内存一起复制，因此子进程开始时与父进程拥有完全相同的打开文件。系统调用 exec 替换调用进程的内存但保留其文件表。这种行为使外壳能够通过 fork、重新打开所选文件描述符然后 exec 新程序来实现 I/O 重定向。下面是外壳为命令 cat <input.txt 所运行代码的简化版本：

```c
char *argv[2];
argv[0] = "cat";
argv[1] = 0;
if(fork() == 0) {
close(0);
open("input.txt", O_RDONLY);
exec("cat", argv);
}
```

子进程关闭文件描述符 0 后，open 保证使用该文件描述符打开新的 input.txt：0 将是最小的可用文件描述符。于是 cat 以文件描述符 0（标准输入）指向 input.txt 来执行。xv6 外壳中 I/O 重定向的代码正是如此工作的 (7930)。回想一下，此时代码中外壳已经 fork 出子外壳，runcmd 将调用 exec 加载新程序。现在应该清楚了为什么把 fork 和 exec 分成两个调用是个好主意：这种分离允许外壳在子进程运行目标程序之前修复子进程。

尽管 fork 复制文件描述符表，但每个底层文件的偏移量在父进程与子进程之间共享。考虑这个例子：

```c
if(fork() == 0) {
write(1, "hello ", 6);
exit();
} else {
wait();
write(1, "world\n", 6);
}
```

这个片段结束时，文件描述符 1 所附着的文件将包含数据 hello world。父进程的 write（由于 wait，只在子进程结束后运行）从子进程 write 结束的地方继续。这一行为有助于产生 shell 命令序列的顺序输出，比如 (echo hello; echo world) >output.txt。

dup 系统调用复制一个已有的文件描述符，返回一个引用同一底层 I/O 对象的新描述符。与 fork 复制的文件描述符一样，两个文件描述符共享一个偏移量。这是把 hello world 写入文件的另一种方式：

```c
fd = dup(1);
write(1, "hello ", 6);
write(fd, "world\n", 6);
```

如果两个文件描述符是由同一原始文件描述符经一串 fork 和 dup 调用派生而来，它们共享偏移量；否则即使由同一文件的 open 调用产生，它们也不共享偏移量。dup 使外壳能够实现如下命令：ls existing-file non-existing-file > tmp1 2>&1。2>&1 告诉外壳给命令一个与描述符 1 重复的文件描述符 2。已有文件名与不存在文件的错误消息都会出现在文件 tmp1 中。xv6 外壳不支持错误文件描述符的 I/O 重定向，但现在你知道如何实现它了。

文件描述符是一种强大的抽象，因为它隐藏了它们所连接内容的细节：向文件描述符 1 写入的进程可能正写向一个文件、一个像控制台那样的设备，或者一个管道。
