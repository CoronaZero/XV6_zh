# 进程与内存

> 来源：book-rev7.pdf，第 7–16 页（中文翻译）

xv6 进程由用户空间内存（指令、数据与栈）和内核私有的进程专属状态组成。Xv6 提供分时：它在等待执行的进程集合之间透明地切换可用的 CPU。当进程未在执行时，xv6 保存其 CPU 寄存器，并在下次运行该进程时恢复它们。内核为每个进程关联一个进程标识符，即 pid。

进程可以使用 fork 系统调用创建一个新进程。fork 创建一个新进程，称为子进程，其内存内容与调用进程（称为父进程）完全一致。fork 在父进程和子进程中都会返回。在父进程中，fork 返回子进程的 pid；在子进程中，它返回零。例如，考虑下面的程序片段：

```c
int pid;
pid = fork();
if(pid > 0){
printf("parent: child=%d\n", pid);
pid = wait();
printf("child %d is done\n", pid);
} else if(pid == 0){
printf("child: exiting\n");
exit();
} else {
printf("fork error\n");
}
```

exit 系统调用使调用进程停止执行并释放内存和打开的文件等资源。wait 系统调用返回当前进程某个已退出子进程的 pid；如果调用者的所有子进程都尚未退出，wait 会等待其中一个退出。在示例中，输出行

```c
parent: child=1234
child: exiting
```

可能以任意顺序出现，取决于父进程还是子进程先到达各自的 printf。子进程退出后，父进程的 wait 返回，使父进程打印

```c
parent: child 1234 is done
```

注意父进程与子进程使用不同的内存和不同的寄存器执行：在一个进程中修改变量不会影响另一个进程。

exec 系统调用用从文件系统某个文件加载的新内存映像替换调用进程的内存。该文件必须具有特定格式，指明文件的哪一部分保存指令、哪一部分是数据、从哪条指令开始执行等等。xv6 使用 ELF 格式，第 2 章将更详细地讨论它。当 exec 成功时，它不会返回调用程序；相反，从文件加载的指令从 ELF 头部声明的入口点开始执行。exec 接受两个参数：包含可执行文件的文件名，以及字符串参数数组。例如：

```c
char *argv[3];
argv[0] = "echo";
argv[1] = "hello";
argv[2] = 0;
exec("/bin/echo", argv);
printf("exec error\n");
```

这个片段把调用程序替换为运行参数列表 echo hello 的 /bin/echo 程序实例。大多数程序忽略第一个参数，按惯例它指程序的名字。

xv6 外壳使用上述调用代表用户运行程序。外壳的主体结构很简单；见 main (8001)。主循环使用 getcmd 读取命令行输入。然后它调用 fork，fork 创建外壳进程的一个副本。父外壳调用 wait，而子进程运行命令。例如，如果用户向提示符输入了“echo hello”，runcmd 将被以“echo hello”为参数调用。runcmd (7906) 运行实际的命令。对于“echo hello”，它会调用 exec (7926)。如果 exec 成功，子进程将执行 echo 的指令而非 runcmd 的指令。某个时刻 echo 会调用 exit，这会使父进程从 main (8001) 的 wait 返回。你可能会好奇为什么 fork 和 exec 不合并为一个调用；后面我们会看到，分开的创建进程与加载程序的调用是一种巧妙的设计。

Xv6 隐式分配大部分用户空间内存：fork 分配子进程复制父进程内存所需的内存，exec 分配足以容纳可执行文件的内存。需要在运行时获得更多内存（也许是为了 malloc）的进程可以调用 sbrk(n) 将数据内存扩大 n 字节；sbrk 返回新内存的位置。

Xv6 不提供用户的概念，也不提供用户之间的保护；用 Unix 的话说，所有 xv6 进程都以 root 身份运行。
