# 文件系统

> 来源：book-rev7.pdf，第 7–16 页（中文翻译）

xv6 文件系统提供数据文件（不可解释的字节数组）和目录（包含对数据文件和其他目录的具名引用）。Xv6 将目录实现为一种特殊类型的文件。目录构成一棵树，从名为根的特特殊目录开始。像 /a/b/c 这样的路径，指的是根目录 / 下名为 a 的目录内名为 b 的目录中名为 c 的文件或目录。不以 / 开头的路径相对于调用进程的当前目录计算，当前目录可以用 chdir 系统调用改变。下面两个代码片段打开同一个文件（假设所涉及的所有目录都存在）：

```c
chdir("/a");
chdir("b");
open("c", O_RDONLY);
open("/a/b/c", O_RDONLY);
```

第一个片段把进程的当前目录改为 /a/b；第二个片段既不引用也不修改进程的当前目录。

有多个系统调用可创建新文件或新目录：mkdir 创建新目录，带 O_CREATE 标志的 open 创建新数据文件，mknod 创建新设备文件。下面这个例子说明了全部三个：

```c
mkdir("/dir");
fd = open("/dir/file", O_CREATE|O_WRONLY);
close(fd);
mknod("/console", 1, 1);
```

mknod 在文件系统中创建一个文件，但该文件没有内容。相反，文件的元数据将其标记为设备文件，并记录主、从设备号（mknod 的两个参数），它们唯一标识一个内核设备。当进程之后打开该文件时，内核会把 read 和 write 系统调用转交内核的设备实现，而不是传给文件系统。

fstat 检索文件描述符所指对象的信息。它填充一个 struct stat，stat.h 中将其定义为：

```c
#define T_DIR 1 // Directory
#define T_FILE 2 // File
#define T_DEV 3 // Device
struct stat {
short type; // Type of file
int dev; // File system's disk device
uint ino; // Inode number
short nlink; // Number of links to file
uint size; // Size of file in bytes
};
```

文件的名字与文件本身是不同的；同一个底层文件（称为 inode）可以有多个名字，称为链接（link）。link 系统调用创建另一个引用与已有文件相同 inode 的文件系统名。这个片段创建了一个名为 a 和 b 两个文件。

```c
open("a", O_CREATE|O_WRONLY);
link("a", "b");
```

对 a 的读写与对 b 的读写相同。每个 inode 由唯一的 inode 号标识。在上述代码序列之后，可以通过检查 fstat 的结果确定 a 和 b 引用相同的底层内容：两者都会返回相同的 inode 号（ino），nlink 计数将为 2。

unlink 系统调用从文件系统移除一个名字。只有当文件的链接计数为零且没有文件描述符引用它时，文件的 inode 与保存其内容的磁盘空间才会被释放。因此在上面的代码序列末尾加上

```c
unlink("a");
```

会把 inode 与文件内容保留为 b 可访问。此外，

```c
fd = open("/tmp/xyz", O_CREATE|O_RDWR);
unlink("/tmp/xyz");
```

是创建临时 inode 的惯用方法，当进程关闭 fd 或退出时会被清理掉。

Xv6 的文件系统操作命令实现为 mkdir、ln、rm 等用户级程序。这种设计允许任何人用新的用户命令扩展外壳。事后看来这一方案显而易见，但 Unix 时代设计的其他系统往往把这些命令构建进外壳（并把外壳构建进内核）。

一个例外是 cd，它构建在外壳内部 (8016)。cd 必须改变外壳自身的当前工作目录。如果 cd 作为普通命令运行，外壳会 fork 一个子进程，子进程运行 cd，cd 会改变子进程的工作目录，而父进程（即外壳）的工作目录不会改变。
