# 多路复用

Xv6 采用这种多路复用方法。当进程等待磁盘请求时，xv6 将其休眠，并调度另一个进程运行。此外，xv6 使用定时器中断在固定时间量（100 毫秒）后强制进程停止在处理器上运行，以便它能在该处理器上调度另一个进程。这种多路复用产生了每个进程都拥有自己的 CPU 的错觉，就像 xv6 使用内存分配器和硬件页表产生每个进程都拥有自己的内存的错觉一样。

实现多路复用有几个挑战。第一，如何从一个进程切换到另一个进程？Xv6 使用标准的上下文切换机制；虽然思想很简单，但实现代码通常是操作系统中最晦涩的代码之一。第二，如何透明地进行上下文切换？Xv6 使用标准技术，用定时器中断处理器驱动上下文切换。第三，许多 CPU 可能同时切换进程，因此需要锁方案避免竞态。第四，当进程退出后，其内存和其他资源必须被释放，但它自己无法完成所有工作，因为例如它不能在仍使用自己的内核栈时释放它。Xv6 试图尽可能简单地解决这些问题，但结果代码仍然棘手。

xv6 必须为进程提供相互协调的方式。例如，父进程可能需要等待某个子进程退出，或者读管道的进程可能需要等待其他进程写入管道。xv6 不会让等待进程通过反复检查所需事件是否发生来浪费 CPU，而是允许进程放弃 CPU 并休眠等待事件，并允许另一个进程唤醒第一个进程。必须注意避免导致事件通知丢失的竞态。作为这些问题及其解决方案的例子，本章考察管道的实现。
