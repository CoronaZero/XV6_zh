# 代码：管道

> 来源：book-rev7.pdf，第 53–66 页（中文翻译）

本章前面使用的简单队列是一个玩具，但 xv6 包含两个真实的、使用 sleep 和 wakeup 同步读写方的队列。一个在 IDE 驱动中：进程把磁盘请求添加到队列，然后调用 sleep。中断处理器使用 wakeup 通知进程其请求已完成。

一个更复杂的例子是管道的实现。我们在第 0 章看到了管道的接口：写入管道一端的数据被复制到内核缓冲区中，然后可以从管道的另一端读出。后续章节将考察围绕管道的文件系统支持，但现在让我们看看 pipewrite 和 piperead 的实现。

每个管道用一个 struct pipe 表示，它包含一把锁和一个数据缓冲区。字段 nread 和 nwrite 统计从缓冲区读取和写入缓冲区的字节数。缓冲区环绕：buf[PIPESIZE-1] 之后写入的下一个字节是 buf[0]，但计数不环绕。这个约定让实现能够区分满缓冲区（nwrite == nread+PIPESIZE）与空缓冲区（nwrite == nread），但它意味着对缓冲区的索引必须使用 buf[nread % PIPESIZE] 而不是 buf[nread]（nwrite 类似）。

假设 piperead 和 pipewrite 的调用同时发生在两个不同的 CPU 上。Pipewrite (6080) 首先获取管道锁，该锁保护计数、数据及其相关不变式。Piperead (6101) 随后也试图获取该锁，但无法做到。它在 acquire (1474) 中自旋等待锁。当 piperead 等待时，pipewrite 循环遍历正在写入的字节——addr[0]、addr[1]、...、addr[n-1]——把每个字节依次加入管道 (6094)。在这个循环中，可能发生缓冲区已满 (6086)。在这种情况下，pipewrite 调用 wakeup 通知任何睡眠中的读者缓冲区中有数据等待，然后在 &p->nwrite 上睡眠，等待读者从缓冲区取走一些字节。sleep 在将 pipewrite 的进程置于睡眠时释放 p->lock。

现在 p->lock 可用，piperead 成功获取它并开始认真运行：它发现 p->nread != p->nwrite (6106)（pipewrite 是因为 p->nwrite == p->nread+PIPESIZE (6086) 才睡眠的），于是进入 for 循环，把数据从管道复制出来 (6113-6117)，并按复制的字节数递增 nread。此时有那么多字节可用于写入，所以 piperead 调用 wakeup (6118) 在返回调用者之前唤醒任何睡眠的写入者。wakeup 找到在 &p->nwrite 上睡眠的进程，即运行 pipewrite 但因缓冲区满而停止的进程。它将该进程标记为 RUNNABLE。

管道代码为读者和写者使用独立的睡眠通道（p->nread 和 p->nwrite）；在不太可能有很多读者和写者等待同一管道的情况下，这可能使系统更高效。管道代码在检查睡眠条件的循环内睡眠；如果有多个读者或写者，除第一个被唤醒的进程外，其他进程都会发现条件仍然为假并再次睡眠。
