# 代码：日志

> 来源：book-rev7.pdf，第 67–81 页（中文翻译）

系统调用中日志的典型用法如下：

```c
begin_trans();
...
bp = bread(...);
bp->data[...] = ...;
log_write(bp);
...
commit_trans();
```

begin_trans (4277) 等待直到获得日志的独占使用，然后返回。log_write (4325) 作为 bwrite 的代理；它将块追加到磁盘上的日志中，并在内存中记录块的扇区号。log_write 将修改后的块保留在内存缓冲区缓存中，以便事务期间对该块的下一次读取得到修改后的块。log_write 注意到在单个事务期间一个块被多次写入，并在日志中覆盖该块之前的副本。

commit_trans (4301) 首先将日志的头部块写入磁盘，使此点之后的崩溃将导致恢复时重新写入日志中的块。commit_trans 然后调用 install_trans (4221) 从日志读取每个块，并将其写入文件系统中的正确位置。最后 commit_trans 写入计数为零的日志头，使下一个事务开始后的崩溃导致恢复代码忽略日志。

recover_from_log (4268) 由 initlog (4205) 调用，initlog 在引导期间、第一个用户进程运行之前被调用。它读取日志头部，如果头部指示日志包含已提交的事务，则模拟 commit_trans 的动作。

日志的一个示例用法出现在 filewrite (5352) 中。事务看起来像这样：

```c
begin_trans();
ilock(f->ip);
r = writei(f->ip, ...);
iunlock(f->ip);
commit_trans();
```

这段代码被包裹在一个循环中，该循环将大的写入拆分成每次只有几个扇区的独立事务，以避免日志溢出。对 writei 的调用作为此事务的一部分写入许多块：文件的 inode、一个或多个位图块，以及一些数据块。对 ilock 的调用发生在 begin_trans 之后，作为整体死锁避免策略的一部分：由于每个事务实际上持有一个锁，避免死锁的锁顺序规则是先事务后 inode。
