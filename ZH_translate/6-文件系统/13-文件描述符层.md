# 文件描述符层

> 来源：book-rev7.pdf，第 67–81 页（中文翻译）

Unix 接口的一个很酷的方面是 Unix 中的大多数资源都表示为文件，包括控制台、管道等设备，当然还有真实文件。文件描述符层就是实现这种统一性的层。

Xv6 为每个进程提供自己的打开文件表，即文件描述符，如我们在第 0 章所见。每个打开的文件由 struct file (3750) 表示，它是 inode 或管道之上的一个包装，加上一个 I/O 偏移量。每次 open 调用都会创建一个新的打开文件（一个新的 struct file）：如果多个进程独立打开同一文件，不同的实例将有不同的 I/O 偏移量。另一方面，单个打开文件（相同的 struct file）可以多次出现在一个进程的文件表中，也可以出现在多个进程的文件表中。如果某个进程用 open 打开文件，然后用 dup 创建别名或用 fork 与子进程共享，就会发生这种情况。引用计数跟踪对特定打开文件的引用数量。文件可以以读、写或读写方式打开。readable 和 writable 字段跟踪这一信息。

系统中所有打开的文件保存在一个全局文件表 ftable 中。文件表有分配文件（filealloc）、创建重复引用（filedup）、释放引用（fileclose）以及读写数据（fileread 和 filewrite）的函数。前三个遵循熟悉的模式。filealloc (5225) 扫描文件表寻找无引用的文件（f->ref == 0）并返回新引用；filedup (5252) 递增引用计数；fileclose (5264) 递减它。当文件的引用计数达到零时，fileclose 根据类型释放底层管道或 inode。

函数 filestat、fileread 和 filewrite 实现对文件 stat、read 和 write 操作。filestat (5302) 只允许在 inode 上调用，它调用 stati。fileread 和 filewrite 检查操作是否被打开模式允许，然后将调用传递给管道或 inode 实现。如果文件表示 inode，fileread 和 filewrite 使用 I/O 偏移量作为操作的偏移量，然后推进它 (5325-5326, 5365-5366)。管道没有偏移量的概念。回想一下，inode 函数要求调用者处理锁定 (5305-5307、5324-5327、5364-5378)。inode 锁定有一个方便的副作用：读写偏移量原子地更新，这样同时向同一文件写入的多个进程不会互相覆盖对方的数据，尽管它们的写入可能交错。
