# 代码：Inode

> 来源：book-rev7.pdf，第 67–81 页（中文翻译）

要分配一个新 inode（例如创建文件时），xv6 调用 ialloc (4603)。ialloc 类似于 balloc：它一次一个块地遍历磁盘上的 inode 结构，寻找标记为空闲的 inode。当它找到一个时，它通过将新类型写入磁盘来占用它，然后以对 iget (4620) 的尾调返回 inode 缓存中的一个条目。ialloc 的正确操作取决于这一事实：同一时间只能有一个进程持有 bp 的引用：ialloc 可以确信其他进程不会同时看到该 inode 可用并试图占用它。

iget (4654) 在 inode 缓存中查找具有所需设备和 inode 号的活动条目（ip->ref > 0）。如果找到，它返回对该 inode 的新引用 (4663-4667)。iget 扫描时，记录第一个空槽的位置 (4668-4669)，如果需要分配缓存条目会用到它。

调用者必须使用 ilock 锁定 inode，然后才能读取或写入其元数据或内容。ilock (4703) 使用现已熟悉的睡眠循环等待 ip->flag 的 I_BUSY 位清除，然后设置它 (4712-4714)。一旦 ilock 获得 inode 的独占访问，如果需要，它可以加载磁盘上的 inode 元数据（更可能是缓冲区缓存）。函数 iunlock (4735) 清除 I_BUSY 位并唤醒所有在 ilock 中睡眠的进程。

iput (4756) 通过递减引用计数 (4772) 释放对 inode 的 C 指针。如果这是最后一个引用，inode 在 inode 缓存中的槽位现在空闲，可以复用于不同的 inode。

如果 iput 看到没有对 inode 的 C 指针引用，且 inode 没有指向它的链接（不出现在任何目录中），那么 inode 及其数据块必须释放。Iput 重新锁定 inode；调用 itrunc 将文件截断为零字节，释放数据块；将 inode 类型设置为 0（未分配）；将更改写入磁盘；最后解锁 inode (4759-4771)。

iput 中的锁定协议值得仔细看看。第一部分值得检查的是，iput 锁定 ip 时，它简单地假定 ip 未加锁，而不是使用睡眠循环。必须如此，因为调用者在调用 iput 之前被要求解锁 ip，并且调用者持有对它的唯一引用（ip->ref == 1）。值得检查的第二部分是 iput 暂时释放 (4764) 并重新获取 (4768) 缓存锁。这是必要的，因为 itrunc 和 iupdate 在磁盘 I/O 期间会睡眠，但我们必须考虑锁不持有期间可能发生什么。具体来说，一旦 iupdate 完成，磁盘上的结构被标记为可再次使用，并发调用 ialloc 可能在 iput 完成之前找到并重新分配它。Ialloc 将通过调用 iget 返回对块的引用，iget 将在缓存中找到 ip，看到其 I_BUSY 标志已设置，并睡眠。此时内核 inode 与磁盘不同步：ialloc 重新初始化了磁盘版本，但依赖调用者在其 iupdate 期间将其加载到内存中。为了确保这发生，iput 在释放 inode 锁之前必须清除 I_BUSY 和 I_VALID。它通过将 flags 清零 (4769) 来实现这一点。
