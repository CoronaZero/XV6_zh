# 代码：系统调用

> 来源：book-rev7.pdf，第 67–81 页（中文翻译）

有了较低层提供的函数，大多数系统调用的实现就很简单了（见 sysfile.c）。有几个调用值得仔细看看。

函数 sys_link 和 sys_unlink 编辑目录，创建或删除对 inode 的引用。它们是使用事务威力的另一个好例子。sys_link (5513) 首先获取其参数，两个字符串 old 和 new (5518)。假设 old 存在且不是目录 (5520-5530)，sys_link 递增其 ip->nlink 计数。然后 sys_link 调用 nameiparent 找到 new 的父目录和最后一个路径元素 (5536)，并创建一个指向 old 的 inode 的新目录项 (5539)。新父目录必须存在，并且与现有 inode 在同一设备上：inode 号只有在单个磁盘上才有唯一意义。如果发生这种错误，sys_link 必须回退并递减 ip->nlink。

事务简化了实现，因为它需要更新多个磁盘块，但我们不必担心更新它们的顺序。它们要么全部成功，要么全部失败。例如，没有事务时，在创建链接之前更新 ip->nlink 会使文件系统暂时处于不安全状态，期间发生崩溃可能导致混乱。有了事务，我们不必担心这一点。

sys_link 为现有 inode 创建一个新名字。函数 create (5657) 为新 inode 创建一个新名字。它是三个文件创建系统调用的泛化：带 O_CREATE 标志的 open 创建普通文件，mkdir 创建新目录，mkdev 创建新设备文件。与 sys_link 一样，create 首先调用 nameiparent 获取父目录的 inode。然后调用 dirlookup 检查名字是否已存在 (5667)。如果名字存在，create 的行为取决于它被用于哪个系统调用：open 与 mkdir 和 mkdev 的语义不同。如果 create 代表 open（type == T_FILE）使用，且已存在的名字本身是普通文件，那么 open 视为成功，因此 create 也视为成功 (5671)。否则，这是错误 (5672-5673)。如果名字尚不存在，create 现在用 ialloc 分配一个新 inode (5676)。如果新 inode 是目录，create 用 . 和 .. 条目初始化它。最后，现在数据已正确初始化，create 可以将其链接到父目录 (5689)。与 sys_link 一样，create 同时持有两个 inode 锁：ip 和 dp。不存在死锁的可能，因为 inode ip 是全新分配的：系统中没有其他进程会持有 ip 的锁然后试图锁定 dp。

使用 create，实现 sys_open、sys_mkdir 和 sys_mknod 很容易。sys_open (5701) 最复杂，因为创建新文件只是它所能做的其中很小一部分。如果 open 传入 O_CREATE 标志，它调用 create (5712)。否则，它调用 namei (5717)。create 返回锁定的 inode，但 namei 不返回，因此 sys_open 必须自己锁定 inode。这提供了一个方便的地方来检查目录只能以只读方式打开。假设 inode 以某种方式获得，sys_open 分配一个文件和一个文件描述符 (5726)，然后填充文件 (5734-5738)。注意，由于它只在当前进程的表中，其他进程无法访问部分初始化的文件。

第 5 章在我们拥有文件系统之前就考察了管道的实现。函数 sys_pipe 通过提供创建管道对的方法，将该实现连接到文件系统。其参数是一个指向两个整数空间的指针，它将在那里记录两个新的文件描述符。然后它分配管道并安装文件描述符。
