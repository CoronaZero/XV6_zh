# 日志设计

> 来源：book-rev7.pdf，第 67–81 页（中文翻译）

日志位于磁盘末端的一个已知固定位置。它由一个头部块后跟一串数据块组成。头部块包含一个扇区号数组，每个被记录的块一个扇区号。头部块还包含记录块的数量。Xv6 在事务提交时写入头部块，之前不写，并在将记录的块复制到文件系统之后将计数设置为零。因此，事务中途崩溃会导致日志头块计数为零；提交后崩溃会导致计数非零。

每个系统调用的代码指示必须原子写入的序列的开始和结束；我们将这样的序列称为事务，尽管它比数据库事务简单得多。任何时刻只能有一个系统调用处于事务中：其他进程必须等待正在进行的事务完成。因此日志一次最多保存一个事务。

Xv6 不允许并发事务，以避免下面这类问题。假设事务 X 已经把一个对 inode 的修改写入了日志。并发事务 Y 随后读取同一块中的不同 inode，更新该 inode，将 inode 块写入日志并提交。这是一个灾难：Y 提交写入磁盘的 inode 块包含 X 的修改，而 X 尚未提交。此时发生崩溃与恢复会暴露 X 的部分修改而非全部修改，从而破坏事务原子性的承诺。解决这个问题有复杂的方法；xv6 通过禁止并发事务来简单解决。Xv6 允许只读系统调用与事务并发执行。inode 锁使事务对只读系统调用看起来是原子的。

Xv6 在磁盘上分配固定空间来容纳日志。任何系统调用都不能写入比日志空间更多的不同块。对大多数系统调用这不是问题，但有两个可能写入很多块：write 和 unlink。大文件的写入可能写许多数据块、许多位图块以及一个 inode 块；取消链接大文件可能写许多位图块和一个 inode。Xv6 的 write 系统调用把大的写操作分解成多个适合日志的小写操作，unlink 不会引起问题，因为实际中 xv6 文件系统只用一个位图块。
