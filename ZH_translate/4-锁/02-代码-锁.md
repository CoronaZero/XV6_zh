# 代码：锁

> 来源：book-rev7.pdf，第 45–52 页（中文翻译）

Xv6 用 struct spinlock (1401) 表示锁。结构中的关键字段是 locked，当锁可用时它为零，持有时非零。逻辑上，xv6 应该通过执行如下代码来获取锁：

```c
21 void
22 acquire(struct spinlock *lk)
23 {
24 for(;;) {
25 if(!lk->locked) {
26 lk->locked = 1;
27 break;
28 }
29 }
30 }
```

不幸的是，这个实现无法在现代多处理器上保证互斥。可能发生两个（或更多）CPU 同时到达第 25 行，看到 lk->locked 为零，然后都通过执行第 26 行和第 27 行获取锁。此时两个不同的 CPU 持有锁，违反了互斥性质。这个 acquire 实现非但没有帮助我们避免竞态，反而有自己的竞态。这里的问题在于第 25 行和第 26 行作为分开的动作执行。为了使上述函数正确，第 25 行和第 26 行必须在一个原子（即不可分割）步骤中执行。

为了原子地执行这两行，xv6 依赖一条特殊的 386 硬件指令 xchg (0569)。在一个原子操作中，xchg 把内存中的一个字与寄存器的内容交换。函数 acquire (1474) 在循环中重复执行这条 xchg 指令；每次迭代读取 lk->locked 并原子地将其设置为 1 (1483)。如果锁被持有，lk->locked 已经是 1，因此 xchg 返回 1，循环继续。但如果 xchg 返回 0，acquire 已经成功获取锁——locked 原来是 0，现在是 1——因此循环可以停止。一旦锁被获取，acquire 记录获取锁的 CPU 和栈轨迹（用于调试）。当进程获取锁后忘记释放时，这些信息有助于找出问题。这些调试字段由锁保护，并且只能在持有锁时编辑。

函数 release (1502) 是 acquire 的相反操作：它清除调试字段，然后释放锁。
