# 代码：使用锁

xv6 在编程中谨慎使用锁来避免竞态。一个简单的例子在 IDE 驱动中 (3800)。如本章开头提到的，iderw (3954) 有一个磁盘请求队列，处理器可能并发地把新请求添加到队列 (3969)。为了保护这个队列和驱动中的其他不变式，iderw 获取 idelock (3965) 并在函数末尾释放。练习 1 探讨如何通过把 acquire 移到队列操作之后来触发本章开头的竞态。尝试这个练习是值得的，因为它会说明触发竞态并不容易，暗示发现竞态 bug 很困难。xv6 中存在一些竞态也并非不可能。

使用锁的一个难点是决定使用多少锁，以及每个锁保护哪些数据和不变式。有几个基本原则。第一，任何时候一个变量可能被一个 CPU 写入，同时另一个 CPU 读取或写入它，都应该引入锁，防止两个操作重叠。第二，记住锁保护不变式：如果不变式涉及多个数据结构，通常需要用一个锁保护所有这些结构，以确保不变式得到维护。

上述规则说明了何时需要锁，但没有说明何时不需要锁。为了效率，不要过度加锁很重要，因为锁会减少并行性。如果效率不重要，那么可以使用单处理器计算机，完全不用担心锁。为了保护内核数据结构，创建一把在进入内核时必须获取、离开内核时必须释放的锁就足够了。许多单处理器操作系统已通过这种方法转换为在多处理器上运行，这种方法有时被称为“巨型内核锁”，但它牺牲了真正的并发性：同一时间只有一个 CPU 能执行内核代码。如果内核执行任何繁重的计算，使用更多更细粒度的锁会更高效，这样内核可以在多个 CPU 上同时执行。

最终，锁粒度的选择是并行编程的练习。xv6 使用少数粗粒度、特定数据结构的锁；例如，xv6 用单锁保护进程表和它的不变式，详见第 5 章。更细粒度的方法是为进程表的每个条目设置一把锁，使处理进程表不同条目的线程可以并行。然而，这会使对整个进程表的不变式操作复杂化，因为它们可能必须获取多把锁。希望 xv6 的例子有助于传达如何使用锁。
