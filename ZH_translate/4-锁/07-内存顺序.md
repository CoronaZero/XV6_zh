# 内存排序

本章一直假设处理器按照指令在程序中出现的顺序启动并完成指令。然而，许多处理器乱序执行指令以获得更高的性能。如果一条指令需要多个周期完成，处理器可能想提前发出该指令，以便与其他指令重叠并避免处理器停顿。例如，处理器可能注意到在串行序列中，指令 A 和 B 相互不依赖，于是先启动 B 再启动 A，这样当处理器完成 A 时 B 也完成了。然而，并发可能把这种重排暴露给软件，导致不正确的行为。

例如，人们可能想知道，如果 release 只是把 0 赋值给 lk->locked 而不是使用 xchg，会发生什么。这个问题的答案尚不清楚，因为不同代 x86 处理器对内存排序提供了不同的保证。如果允许 lk->locked=0 被重新排序，比如说在 popcli 之后，那么 acquire 可能会出问题，因为对另一个线程来说，中断会在锁被释放之前被启用。为了避免依赖关于内存排序的不确定的处理器规格，xv6 不冒险，使用 xchg，处理器必须保证它不会被重新排序。
