# 引言

> 来源：book-rev7.pdf，第 45–52 页（中文翻译）

xv6 运行在多处理器上，即拥有多个独立执行代码的 CPU 的计算机。这些 CPU 在同一个物理地址空间中操作，并共享数据结构；xv6 必须引入一种协调机制，防止它们互相干扰。即使在单处理器上，xv6 也必须使用某种机制来防止中断处理程序与非中断代码相互干扰。xv6 对两者使用相同的底层概念：锁。锁提供互斥，确保任何时候只有一个 CPU 能持有该锁。如果 xv6 只在持有特定锁时才访问某个数据结构，那么 xv6 就可以确信同一时刻只有一个 CPU 在访问该数据结构。在这种情况下，我们说锁保护了该数据结构。

本章其余部分解释 xv6 为什么需要锁、xv6 如何实现它们以及如何使用它们。一个关键观察是：如果你看 xv6 中的一行代码，你必须问自己：是否有另一个处理器可能改变这行代码的预期行为（例如因为另一个处理器也在执行这行代码，或执行另一行修改共享变量的代码），以及如果运行一个中断处理程序会发生什么。在两种情况下，你都必须记住：每一行 C 代码可能对应几条机器指令，因此另一个处理器或一个中断可能穿插在一条 C 指令中间。你不能假设页面上的代码行按顺序执行，也不能假设一条 C 语句会原子地执行。并发使得正确性推理困难得多。
