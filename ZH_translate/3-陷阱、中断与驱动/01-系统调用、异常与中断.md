# 系统调用、异常与中断

> 来源：book-rev7.pdf，第 33–44 页（中文翻译）

正如我们在上一章末尾看到的，通过系统调用，用户程序可以请求操作系统服务。术语“异常”指产生中断的非法程序动作。非法程序动作的例子包括除零、访问不存在 PTE 的内存等等。术语“中断”指硬件设备产生的信号，表示它需要操作系统的注意。例如，时钟芯片可能每 100 毫秒产生一次中断，让内核实现分时。再例如，当磁盘从磁盘读了一个块，它产生一个中断，提醒操作系统该块已准备好被取走。

内核处理所有中断，而不是进程处理它们，因为在大多数情况下只有内核具有所需的特权与状态。例如，为了响应时钟中断在进程之间时间分片，内核必须参与，即使只是为了强制不合作的进程让出处理器。

在全部三种情况下，操作系统设计都必须安排以下事情发生。系统必须保存处理器寄存器以便将来透明恢复。系统必须设置好在内核中执行。系统必须为内核选择一个开始执行的位置。内核必须能够检索关于事件的信息，例如系统调用参数。这一切必须安全完成；系统必须维持用户进程与内核的隔离。

为了实现这一目标，操作系统必须了解硬件如何处理系统调用、异常和中断的细节。在大多数处理器中，这三种事件由单一硬件机制处理。例如，在 x86 上，程序通过用 int 指令产生中断来发起系统调用。同样，异常也会产生中断。因此，如果操作系统对中断处理有完整的方案，那么操作系统就可以处理系统调用和异常。

基本方案如下。中断停止正常的处理器循环，并开始执行一个称为中断处理器的新序列。在开始中断处理器之前，处理器保存其寄存器，以便操作系统在从中断返回时恢复它们。进入和离开中断处理器的一个挑战是，处理器应该在用户模式和内核模式之间切换，然后再切换回来。

关于术语的一点说明：虽然官方 x86 术语是 interrupt，但 xv6 把这些都称为 trap，很大程度上是因为 PDP11/40 使用了这个术语，因此它是 Unix 的传统术语。本章可互换使用 trap 和 interrupt，但重要的是记住：trap 由当前在处理器上运行的进程引起（例如进程发出系统调用从而产生 trap），而 interrupt 由设备引起，可能与当前运行的进程无关。例如，磁盘为一个进程取回块完成时会产生中断，但中断发生时可能正在运行另一个进程。中断的这一特性使思考中断比思考 trap 更困难，因为中断与其他活动并发发生。然而，两者都依赖相同的硬件机制来安全地在用户与内核模式之间转移控制，我们接下来将讨论这一点。
