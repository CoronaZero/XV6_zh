# x86 保护

> 来源：book-rev7.pdf，第 33–44 页（中文翻译）

x86 有 4 个保护级别，编号为 0（最高特权）到 3（最低特权）。实践中，大多数操作系统只用两个级别：0 和 3，分别称为内核模式和用户模式。x86 执行指令的当前特权级别存储在 %cs 寄存器的 CPL 字段中。

在 x86 上，中断处理程序定义在中断描述符表（IDT）中。IDT 有 256 个条目，每个条目给出处理相应中断时使用的 %cs 和 %eip。

要在 x86 上发起系统调用，程序调用 int n 指令，其中 n 指定 IDT 的索引。int 指令执行以下步骤：

- 从 IDT 获取第 n 个描述符，其中 n 是 int 的参数。
- 检查 %cs 中的 CPL 是否 <= DPL，其中 DPL 是描述符中的特权级别。
- 仅当目标段选择子的 PL < CPL 时，把 %esp 和 %ss 保存到 CPU 内部寄存器中。
- 从任务段描述符加载 %ss 和 %esp。
- 压入 %ss。
- 压入 %esp。
- 压入 %eflags。
- 压入 %cs。
- 压入 %eip。
- 清除 %eflags 的某些位。
- 将 %cs 和 %eip 设置为描述符中的值。

（图 3-1：int 指令之后的内核栈——esp 以下为空；esp 之上是错误代码、eip、cs、eflags、esp（仅特权级变化时存在）、ss（仅特权级变化时存在，来自任务段）。）

int 指令是一条复杂指令，人们可能会想这些动作是否都是必要的。CPL <= DPL 的检查允许内核禁止某些特权级的系统调用。例如，用户程序要成功执行 int 指令，DPL 必须是 3。如果用户程序没有适当的特权，int 指令将导致 int 13，即一般保护异常。再例如，int 指令不能使用用户栈保存值，因为用户可能没有设置合适的栈，因此硬件使用任务段中指定的栈，而任务段在内核模式下设置。

图 3-1 显示了 int 指令完成后、且发生特权级变化时（描述符中的特权级低于 CPL）的栈。如果 int 指令不需要特权级变化，x86 不会保存 %ss 和 %esp。两种情况下，%eip 都指向描述符表中指定的地址，该地址处的指令是下一条要执行的指令，也是 int n 处理程序的第一条指令。实现这些处理程序是操作系统的职责，下面我们将看到 xv6 是怎么做的。

操作系统可以使用 iret 指令从 int 指令返回。它从栈中弹出 int 指令期间保存的值，并在保存的 %eip 处恢复执行。
