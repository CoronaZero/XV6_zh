# 代码：C trap 处理器

> 来源：book-rev7.pdf，第 33–44 页（中文翻译）

我们在上一节看到，每个处理器建立一个 trap frame，然后调用 C 函数 trap。Trap (3101) 查看硬件 trap 号 tf->trapno，以决定为什么被调用以及需要做什么。如果 trap 是 T_SYSCALL，trap 调用系统调用处理器 syscall。我们将在第 5 章重新讨论 cp->killed 的两个检查。

检查系统调用之后，trap 查找硬件中断（我们在下面讨论）。除预期中的硬件设备之外，trap 也可能由虚假中断（不需要的硬件中断）引起。

如果 trap 不是系统调用，也不是寻求关注的硬件设备，trap 假定它由 trap 之前正在执行的代码中的错误行为（如除零）引起。如果引起 trap 的代码是用户程序，xv6 打印详细信息，然后设置 cp->killed 以记住清理用户进程。我们将在第 5 章看到 xv6 如何做这种清理。如果运行的是内核，那一定是内核 bug：trap 打印有关意外情况的详细信息，然后调用 panic。
