# 代码：中断

> 来源：book-rev7.pdf，第 33–44 页（中文翻译）

主板上的设备可以产生中断，xv6 必须设置硬件来处理这些中断。没有设备支持，xv6 将无法使用；用户无法在键盘上键入，文件系统无法将数据存储在磁盘上，等等。幸运的是，添加中断和对简单设备的支持并不需要太多额外的复杂性。正如我们将看到的，中断可以使用与系统调用和异常相同的代码。

中断与系统调用相似，区别在于设备随时产生中断。主板上有硬件在设备需要关注时向 CPU 发信号（例如用户在键盘上键入了一个字符）。我们必须对设备编程以产生中断，并安排某个 CPU 接收中断。

让我们看看定时器设备和定时器中断。我们希望定时器硬件每秒产生大约 100 次中断，这样内核可以跟踪时间的流逝，并且可以在多个运行进程之间进行时间分片。选择每秒 100 次允许良好的交互性能，同时不会让处理器陷入处理中断的泥潭。

与 x86 处理器本身一样，PC 主板也在演进，提供中断的方式也在演进。早期主板有一个简单的可编程中断控制器（称为 PIC），你可以在 picirq.c 中找到管理它的代码。随着多处理器 PC 主板的出现，需要一种处理中断的新方式，因为每个 CPU 需要一个中断控制器来处理发送给它的中断，并且必须有一种方法将中断路由到处理器。这种方式由两部分组成：一部分在 I/O 系统中（IO APIC，ioapic.c），一部分连接到每个处理器（本地 APIC，lapic.c）。Xv6 面向多处理器主板设计，每个处理器都必须编程以接收中断。

为了也能在单处理器上正确工作，Xv6 对可编程中断控制器 (PIC) (6932) 编程。每个 PIC 最多可处理 8 个中断（即设备）并将它们多路复用到处理器引脚上。为了允许超过 8 个设备，PIC 可以级联，典型主板至少有 2 个。使用 inb 和 outb 指令，xv6 对主 PIC 编程以产生 IRQ 0 到 7，从 PIC 产生 IRQ 8 到 16。最初 xv6 将 PIC 编程为屏蔽所有中断。timer.c 中的代码设置定时器 1 并启用 PIC 上的定时器中断 (7574)。此描述省略了一些编程 PIC 的细节。这些 PIC 的细节（以及 IOAPIC 和 LAPIC）对本文来说不重要，感兴趣的读者可以查阅每个设备的参考手册，这些手册在源文件中被引用。

在多处理器上，xv6 必须对 IOAPIC 和每个处理器上的 LAPIC 编程。IO APIC 有一个表，处理器可以通过内存映射 I/O（而不是 inb 和 outb 指令）来编程表中的条目。在初始化期间，xv6 编程将中断 0 映射到 IRQ 0，依此类推，但禁用所有中断。特定设备启用特定的中断，并说明中断应路由到哪个处理器。例如，xv6 将键盘中断路由到处理器 0 (7516)。xv6 将磁盘中断路由到系统上编号最高的处理器，我们将在下面看到。

定时器芯片位于 LAPIC 内部，因此每个处理器可以独立接收定时器中断。Xv6 在 lapicinit (6651) 中设置它。关键行是编程定时器的那行 (6664)。该行告诉 LAPIC 定期在 IRQ_TIMER（即 IRQ 0）产生中断。第 6693 行使 CPU 的 LAPIC 上启用中断，这将使中断传送到本地处理器。

处理器可以通过 eflags 寄存器中的 IF 标志控制是否要接收中断。cli 指令通过清除 IF 来禁用处理器上的中断，sti 指令启用处理器上的中断。Xv6 在主 CPU 启动 (8412) 和其他处理器启动 (1126) 期间禁用中断。每个处理器上的调度器启用中断 (2464)。为了控制某些代码段不被中断，xv6 在这些代码段期间禁用中断（例如，见 switchuvm (1773)）。

定时器通过向量 32 中断（xv6 选择它处理 IRQ 0），xv6 在 idtinit (1265) 中设置。向量 32 和向量 64（用于系统调用）之间的唯一区别是向量 32 是中断门而不是 trap 门。中断门清除 IF，因此被中断的处理器在处理器处理当前中断时不会接收中断。从这一点到 trap，中断与系统调用和异常使用相同的代码路径构建 trap frame。

当 trap 被调用于时间中断时，它只做两件事：递增 ticks 变量 (3063)，并调用 wakeup。后者正如我们将在第 5 章看到的，可能使中断返回到另一个进程。
