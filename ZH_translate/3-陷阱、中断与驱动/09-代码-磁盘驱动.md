# 代码：磁盘驱动

> 来源：book-rev7.pdf，第 33–44 页（中文翻译）

IDE 设备提供对连接到 PC 标准 IDE 控制器的磁盘的访问。IDE 现在正被 SCSI 和 SATA 取代，但它的接口简单，让我们能集中关注驱动程序的总体结构，而不是某个特定硬件设备的细节。

磁盘驱动用一种称为缓冲区的数据结构表示磁盘扇区，struct buf (3500)。每个缓冲区代表特定磁盘设备上一个扇区的内容。dev 和 sector 字段给出设备号与扇区号，data 字段是磁盘扇区的内存副本。

flags 跟踪内存与磁盘之间的关系：B_VALID 标志表示数据已读入，B_DIRTY 标志表示数据需要写出。B_BUSY 标志是一个锁位；它表示某个进程正在使用该缓冲区，其他进程不得使用。当缓冲区设置了 B_BUSY 标志时，我们说缓冲区被锁定。

内核在引导时通过 main (1234) 调用 ideinit (3851) 初始化磁盘驱动。ideinit 调用 picenable 和 ioapicenable 启用 IDE_IRQ 中断 (3856-3857)。picenable 调用在单处理器上启用中断；ioapicenable 在多处理器上启用中断，但只在最后一个 CPU（ncpu-1）上：在两处理器系统上，CPU 1 处理磁盘中断。

接下来，ideinit 探测磁盘硬件。它首先调用 idewait (3858) 等待磁盘能够接受命令。PC 主板在 I/O 端口 0x1f7 上呈现磁盘硬件的状态位。idewait (3833) 轮询状态位，直到忙位（IDE_BSY）清除且就绪位（IDE_DRDY）设置。

现在磁盘控制器已就绪，ideinit 可以检查存在多少个磁盘。它假定磁盘 0 存在，因为引导加载器与内核都是从磁盘 0 加载的，但它必须检查磁盘 1。它向 I/O 端口 0x1f6 写入以选择磁盘 1，然后等待一段时间，让状态位显示磁盘就绪 (3860-3867)。如果未就绪，ideinit 假定磁盘不存在。

ideinit 之后，磁盘不会再次使用，直到缓冲区缓存调用 iderw，它根据标志更新已锁定的缓冲区。如果设置了 B_DIRTY，iderw 把缓冲区写入磁盘；如果未设置 B_VALID，iderw 从磁盘读取缓冲区。

磁盘访问通常需要毫秒级的时间，这对处理器来说是很长的时间。引导加载器发出磁盘读命令，并反复读取状态位直到数据就绪。这种轮询（polling）或忙等待在引导加载器中是好的，因为它没有更好的事情可做。然而，在操作系统中，更高效的做法是让另一个进程在 CPU 上运行，并安排在磁盘操作完成时收到中断。Iderw 采用后一种方法，维护一个待处理磁盘请求的队列，并使用中断来知道每个请求何时完成。尽管 iderw 维护请求队列，简单的 IDE 磁盘控制器一次只能处理一个操作。磁盘驱动维护一个不变式：它已把队列前端的缓冲区发送给磁盘硬件；其余缓冲区只是在等待轮到它们。

Iderw (3954) 把缓冲区 b 添加到队列末尾 (3967-3971)。如果缓冲区位于队列前面，iderw 必须通过调用 idestart (3924-3926) 把它发送到磁盘硬件；否则，缓冲区将等到它前面的缓冲区被处理完再启动。

idestart (3875) 根据标志为缓冲区的设备发出读或写命令，根据标志。如果操作是写，idestart 现在必须提供数据 (3889)，中断将信号表示数据已写入磁盘。如果操作是读，中断将信号表示数据就绪，处理器将读取它。注意，iderw 对 IDE 设备有详细的了解，并在正确的端口写入正确的值。如果这些 outb 语句中任何一个错误，IDE 会做一些与我们期望不同的事情。弄对这些细节是编写设备驱动程序挑战的原因之一。

请求加入队列并（如果需要）启动后，iderw 必须等待结果。如前所述，轮询不能有效地利用 CPU。相反，iderw 睡眠，等待中断处理器在缓冲区标志中记录操作完成 (3978-3979)。此进程睡眠时，xv6 将调度其他进程以保持 CPU 忙碌。

最终磁盘将完成操作并触发中断。trap 将调用 ideintr 处理它 (3124)。ideintr (3902) 检查队列中的第一个缓冲区，找出正在进行的操作。如果缓冲区正在被读且磁盘控制器有数据等待，ideintr 用 insl 把数据读入缓冲区 (3915-3917)。现在缓冲区已就绪：ideintr 设置 B_VALID，清除 B_DIRTY，并唤醒所有在缓冲区上睡眠的进程 (3919-3922)。最后，ideintr 必须把下一个等待的缓冲区交给磁盘 (3924-3926)。
