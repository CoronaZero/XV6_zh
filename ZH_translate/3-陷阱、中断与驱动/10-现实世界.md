# 现实世界

> 来源：book-rev7.pdf，第 33–44 页（中文翻译）

在 PC 主板上支持所有设备是一项浩大的工程，因为设备众多，设备功能丰富，设备与驱动之间的协议也可能复杂。在许多操作系统中，驱动加起来的代码比核心内核还多。

实际的设备驱动比本章中的磁盘驱动复杂得多，但基本思想是相同的：设备通常比 CPU 慢，因此硬件用中断来通知操作系统状态的变化。现代磁盘控制器通常一次接受多个未完成的磁盘请求，甚至会重新排列它们，以最有效地利用磁盘臂。当磁盘更简单时，操作系统通常自己重新排列请求队列。

许多操作系统有固态硬盘的驱动，因为它们提供更快的数据访问。但尽管固态硬盘与传统机械磁盘工作方式非常不同，两者都提供基于块的接口，且固态硬盘上读写块仍然比读写 RAM 昂贵。

其他硬件与磁盘惊人地相似：网络设备缓冲区保存数据包，音频设备缓冲区保存声音样本，图形卡缓冲区保存视频数据和命令序列。高带宽设备——磁盘、图形卡和网络卡——通常使用直接内存访问（DMA）而不是本驱动中的显式 I/O（insl、outsl）。DMA 允许磁盘或其他控制器直接访问物理内存。驱动把缓冲区 data 字段的物理地址交给设备，设备直接从主内存复制数据或把数据复制到主内存，复制完成后中断。使用 DMA 意味着 CPU 完全不参与传输，这更高效，也减轻了 CPU 内存缓存的压力。

本章中的大多数设备使用 I/O 指令来编程，反映了这些设备较老。所有现代设备都使用内存映射 I/O 编程。

某些驱动在轮询与中断之间动态切换，因为使用中断可能昂贵，但使用轮询可能引入延迟，直到驱动处理事件。例如，对于收到突发数据包的网络驱动，可能会从中断切换到轮询，因为它知道必须处理更多数据包，并且用轮询处理成本更低。一旦不需要处理更多包，驱动可以切回中断，以便新包到达时立即得到提醒。

IDE 驱动将中断静态路由到一个特定处理器。某些驱动有复杂的中断路由算法，使处理包负载在处理器间均匀且保持良好的局部性。例如，网络驱动可能安排把某个网络连接的包的中断传送给管理该连接的处理器，同时其他连接的数据包的中断传送给另一个处理器。这种路由可能变得相当复杂；例如，如果某些网络连接寿命短，而另一些寿命长，且操作系统希望所有处理器保持忙碌以实现高吞吐量。

如果用户进程读取文件，该文件的数据被复制两次。首先，驱动将数据从磁盘复制到内核内存，然后 read 系统调用将数据从内核空间复制到用户空间。如果用户进程随后将数据发送到网络，则数据又会被复制两次：一次从用户空间复制到内核空间，一次从内核空间复制到网络设备。为了支持低延迟重要的应用（例如提供静态网页的 Web 服务器），操作系统使用特殊的代码路径来避免这些多次复制。一个例子是，在实际操作系统中，缓冲区通常与硬件页大小匹配，因此只读副本可以使用分页硬件映射到进程的地址空间，而无需任何复制。
