# 代码：系统调用

> 来源：book-rev7.pdf，第 33–44 页（中文翻译）

对于系统调用，trap 调用 syscall (3375)。syscall 从 trap frame（包含保存的 %eax）加载系统调用号，并索引系统调用表。对于第一个系统调用，%eax 包含值 SYS_exec (3207)，syscall 将调用系统调用表的第 SYS_exec 个条目，即调用 sys_exec。

syscall 将系统调用函数的返回值记录在 %eax 中。当 trap 返回用户空间时，它会将 cp->tf 中的值加载到机器寄存器。因此，当 exec 返回时，它将返回系统调用处理程序返回的值 (3381)。系统调用通常返回负数表示错误，返回正数表示成功。如果系统调用号无效，syscall 打印错误并返回 –1。

后面的章节将考察特定系统调用的实现。本章关注系统调用的机制。还有一点机制需要说明：查找系统调用参数。辅助函数 argint、argptr 和 argstr 检索第 n 个系统调用参数，参数可以是整数、指针或字符串。argint 使用用户空间的 %esp 寄存器定位第 n 个参数：%esp 指向系统调用存根的返回地址，参数就在它上方，即 %esp+4。于是第 n 个参数位于 %esp+4+4*n。

argint 调用 fetchint 从用户内存读取该地址的值并写入 *ip。fetchint 可以简单地把地址强制转换为指针，因为用户与内核共享同一张页表，但内核必须验证用户传递的指针确实是地址空间用户部分的指针。内核已经设置了页表硬件，确保进程无法访问其本地私有内存之外的内存：如果用户程序尝试读取或写入 p->sz 或更高地址处的内存，处理器将产生一个分段 trap，trap 会杀死进程，正如我们上面看到的。而现在，内核正在运行，它可以解引用用户可能传递的任何地址，因此必须显式检查该地址低于 p->sz。

argptr 与 argint 目的类似：它解释第 n 个系统调用参数。argptr 调用 argint 以整数形式获取参数，然后检查该整数作为用户指针是否确实在地址空间的用户部分。注意，在调用 argptr 期间发生两次检查。第一次，用户栈指针在获取参数时被检查。然后参数本身（本身是一个用户指针）被检查。

argstr 是三个系统调用参数辅助函数中的最后一个。它将第 n 个参数解释为指针。它确保该指针指向 NUL 结尾的字符串，并且完整字符串的末尾不超过地址空间用户部分的上界。

系统调用实现（例如 sysproc.c 和 sysfile.c）通常是包装器：它们用 argint、argptr 和 argstr 解码参数，然后调用真正的实现。在第 2 章中，sys_exec 使用这些函数获取其参数。
