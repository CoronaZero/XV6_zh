# 代码：物理内存分配器

> 来源：book-rev7.pdf，第 25–32 页（中文翻译）

分配器的数据结构是一个可用物理内存页的空闲链表。每个空闲页的链表元素是一个 struct run (2764)。分配器从哪里获得内存来存放这个数据结构呢？它把每个空闲页的 run 结构存放在空闲页自身中，因为那里没有存储别的东西。空闲链表由自旋锁保护 (2764-2766)。链表和锁被包裹在一个 struct 中，以明确锁保护的是 struct 中的字段。现在先忽略锁以及 acquire 和 release 的调用；第 4 章将详细考察锁。

函数 main 调用 kinit1 和 kinit2 初始化分配器 (2780)。之所以有两次调用，是因为在 main 的大部分时间里，不能使用锁或 4 兆字节以上的内存。kinit1 调用在最初 4 兆字节内建立无锁分配，kinit2 调用启用锁并安排更多可分配的内存。main 本应确定有多少可用物理内存，但在 x86 上这很困难。相反，它假定机器有 240 兆字节（PHYSTOP）的物理内存，并把内核结束到 PHYSTOP 之间的所有内存作为初始空闲内存池。kinit1 和 kinit2 调用 freerange，通过逐页调用 kfree 把内存添加到空闲链表。PTE 只能引用在 4096 字节边界对齐（是 4096 的倍数）的物理地址，因此 freerange 使用 PGROUNDUP 确保只释放对齐的物理地址。分配器开始时没有内存；这些 kfree 调用给了它一些内存来管理。

分配器用物理页在高内存中映射的虚拟地址（而不是其物理地址）来引用物理页，这就是为什么 kinit 使用 p2v(PHYSTOP) 把 PHYSTOP（一个物理地址）翻译为虚拟地址。分配器有时把地址当作整数来做算术（例如在 kinit 中遍历所有页），有时把地址当作指针读写内存（例如操作存储在每个页中的 run 结构）；这种地址的双重使用是分配器代码充满 C 类型转换的主要原因。另一个原因在于释放和分配本身就改变了内存的类型。

函数 kfree (2815) 首先把被释放内存中的每个字节设置为值 1。这将导致在释放后使用内存的代码（使用“悬空引用”）读到垃圾数据而不是旧的合法内容；希望这能使此类代码更快地崩溃。然后 kfree 把 v 转换为指向 struct run 的指针，在 r->next 中记录旧链表头，并把空闲链表设为 r。kalloc 移除并返回空闲链表的第一个元素。
