# 进程地址空间

> 来源：book-rev7.pdf，第 25–32 页（中文翻译）

entry 创建的页表有足够的映射让内核的 C 代码开始运行。但是，main 立即调用 kvmalloc (1757) 切换到一张新页表，因为内核对于描述进程地址空间有更周密的计划。

每个进程都有一张独立的页表，xv6 在进程间切换时会让页表硬件切换页表。如图 2-2 所示，进程的用户内存从虚拟地址 0 开始，可以增长到 KERNBASE，允许进程寻址多达 2 GB 的内存。当进程向 xv6 请求更多内存时，xv6 首先找到空闲物理页提供存储，然后把指向新物理页的 PTE 添加到进程的页表中。xv6 在这些 PTE 中设置 PTE_U、PTE_W 和 PTE_P 标志。大多数进程不会用完整个用户地址空间；xv6 在未使用的 PTE 中保持 PTE_P 清除。不同进程的页表把用户地址翻译到物理内存的不同页，因此每个进程都有私有的用户内存。

xv6 在每张进程页表中都包含内核运行所需的所有映射；这些映射都出现在 KERNBASE 之上。它将虚拟地址 KERNBASE:KERNBASE+PHYSTOP 映射到 0:PHYSTOP。这种映射的一个原因是让内核能使用自己的指令和数据。另一个原因是内核有时需要能够写入物理内存的某个给定页，例如创建页表页时；让每个物理页出现在可预测的虚拟地址上会很方便。这种安排的一个缺陷是 xv6 无法使用超过 2 GB 的物理内存。某些使用内存映射 I/O 的设备出现在从 0xFE000000 开始的物理地址，因此 xv6 页表为它们包含直接映射。Xv6 不在 KERNBASE 之上的 PTE 中设置 PTE_U 标志，所以只有内核可以使用它们。

每个进程的页表都包含用户内存和整个内核的映射，这在系统调用和中断期间从用户代码切换到内核代码时很方便：这种切换不需要切换页表。

（继续：）在大多数情况下，内核没有自己的页表；它几乎总是借用某个进程的页表。

回顾一下：xv6 确保每个进程只能使用自己的内存，并确保每个进程看到的内存是从 0 开始的连续虚拟地址。xv6 通过只在指向进程自身内存的虚拟地址的 PTE 上设置 PTE_U 位来实现第一点；利用页表把连续的虚拟地址翻译到恰好分配给进程的任意物理页的能力来实现第二点。
