# 现实世界

> 来源：book-rev7.pdf，第 25–32 页（中文翻译）

与大多数操作系统一样，xv6 使用分页硬件进行内存保护和映射。大多数操作系统对分页的利用远比 xv6 复杂；例如，xv6 缺少磁盘请求分页、写时复制 fork、共享内存、懒分配页和自动扩展栈。x86 支持使用分段进行地址翻译（见附录 B），但 xv6 只将分段用于常见的技巧：实现像 proc 这样的每 CPU 变量，它们位于固定地址但在不同 CPU 上有不同的值（见 seginit）。在非分段架构上实现每 CPU（或每线程）存储需要专门用一个寄存器保存指向每 CPU 数据区的指针，但 x86 的通用寄存器太少，因此使用分段所付出的额外努力是值得的。

在内存很多的机器上，使用 x86 的 4 Mbyte“大页”可能是有意义的。当物理内存较小时，小页有意义，这样可以细粒度地分配和换出到磁盘。例如，如果程序只使用 8 Kbyte 内存，给它一个 4 Mbyte 物理页就浪费了。大页在拥有大量 RAM 的机器上有意义，并可能减少页表操作的（页表）开销。Xv6 在一处使用了大页：初始页表 (1311)。数组初始化设置了 1024 个 PDE 中的两个，位于索引 0 和 960（KERNBASE>>PDXSHIFT）处，其余 PDE 为零。Xv6 在这两个 PDE 中设置 PTE_PS 位，将它们标记为大页。内核还通过在 %cr4 中设置 CR_PSE 位（Page Size Extension，页大小扩展）告诉分页硬件允许大页。

xv6 应该确定实际的 RAM 配置，而不是假设 240 MB。在 x86 上，至少有三种常用算法：第一种是探测物理地址空间，寻找行为像内存并保留写入值的区域；第二种是从 PC 的非易失性 RAM 中已知的 16 位位置读取内存的千字节数；第三种是查看 BIOS 内存中的内存布局表，该表作为多处理器表的一部分。读取内存布局表很复杂。

内存分配是一个古老的热门话题，其基本问题是有限内存的高效利用以及为未知的未来请求做准备；见 Knuth。今天人们更关心速度而非空间效率。此外，一个更复杂的内核很可能会分配许多不同大小的小块，而不是像 xv6 那样只分配 4096 字节的块；真正的内核分配器需要处理小型和大型分配。
